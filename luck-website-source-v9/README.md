# luck 网页预览

React + TypeScript + Vite + Tailwind CSS 的完整本地演示前端。品牌依据 `LUCK-Codex-Prompt.md`，新版采用墨绿与金色开奖舞台、0–19 转盘，以及白衬衫、绿马甲荷官牌桌。使用用户提供的正式皇冠、8 号球与金色 LUCK 缎带代币 Logo。

## 启动与验证

需要 Node.js 22.12+（本次使用 Node.js 24）。

```sh
npm install
npm run dev -- --port 5188
```

打开 http://127.0.0.1:5188/ 。默认 `npm run dev` 使用 5173；如已占用请指定其他端口。

```sh
npm run test       # 金额、选号、结算与资金守恒测试
npm run typecheck  # TypeScript 检查
npm run build     # 生成 dist/
npm run preview -- --port 5189
```

所有子路由都可以直接打开和刷新。部署静态站时需要将未知路径回退到 `index.html`（SPA fallback）；Vite 开发与预览服务器已支持。

## 页面

- `/`：价格、每日与快速挑战、独立统计、最近开奖。
- `/daily`：0–19 选号、普通 / 五种复式、机选、倍数与报价确认。
- `/quick`：小 / 豹子 / 大、动态资金权重与参考到账、参与与最近记录。
- `/pools`：独立金库、五档余额 / 预计释放、规则、合约接入状态、演示资金流。
- `/history`：游戏切换、期号搜索、分页与开奖结算详情。
- `/account`：演示余额、订单、奖励、快速本金 / 净盈利 / 销毁 / 到账、单项及全部领取。

## 演示完整流程

1. 点击“连接钱包”，选择“luck 演示钱包”。起始余额为 250,000 luck，地址具有明显 `DEMO-` 前缀。
2. 每日挑战选择 2–6 个号码；复式必须达到所选模式的确切数量，其中 7包6 支持 7 个。选择倍数，获取报价并确认演示参与。
3. 快速挑战选择阵营和倍数。确认单根据自己的 luck 本金与锁定 U 权重计算参考回报。
4. 到点后自动封盘、等待数据、展示开奖结果与完成演示结算。每日转盘依次停在六个结果号码；快速骰战在开奖前最后 10 秒封盘并进入摇骰状态。结果只读取服务返回的数据。
5. “让我的最新订单命中”仅为开发测试开关。关闭后使用演示随机结果；真实随机数来源未接入。
6. 到个人中心领取。完成后按钮禁用，已领取项目不会重复计入余额。
7. 点击舞台上的“体验开奖”可提前体验一次完整流程；结算展示结束后自动进入下一期。开发设置仍可手动推进。所有参与、派奖与领取仅更新本地演示数据。

演示状态保存在当前浏览器的 `localStorage` 键 `luck-preview-v1` 中。切换页面、刷新、重启预览不会重置截止时间或订单。需要全新演示时可在浏览器开发者工具中删除此键并刷新；这会清除当前本地演示订单。

## 配置、资产与服务

### 赌场光影背景

当前使用独立编写的 `src/components/CasinoLight.tsx` 与同名 CSS，无需授权密钥、外部服务或额外依赖；不是 React Bits Pro 的 Dappled Light 组件。首页两张游戏卡、每日转盘舞台和荷官牌桌已接入。

暖金色取自 `--gold`，柔化的四叶草与菱形光斑缓慢移动，配合吊灯反光。牌桌中心使用遮罩保持荷官面部和骰盅清晰；光层不接收点击。Canvas 最长边限制为 960 像素，以最多约 24 帧/秒绘制；页面隐藏或光层滚出视口时停止绘制，系统开启减少动态效果时显示静态光影。

之前配置的 React Bits Pro Starter / Pro 仓库保留在 `components.json`，仅供以后有授权时安装使用，当前运行不依赖它们。如以后安装官方组件，请按[官方安装说明](https://pro.reactbits.dev/docs/installation)向安装进程提供 `REACTBITS_LICENSE_KEY`，不要使用 `VITE_` 前缀或把密钥写入源码。

### 10 秒摇骰视频

`DealerFilm.tsx` / CSS 在快速牌桌接入 `/assets/dealer-shake-10s.mp4`，来源为用户提供的桌面视频。视频保留拿起、摇晃、放回骰盅的完整动作。仅使用不含两处角落水印的中央画面，两侧以用户新提供的同场景参考图补齐，并用 64px 羽化衔接。原视频和参考图未改动，全部在本地处理。成片 H.264 / AAC、1280×720、24fps、10 秒，支持网页快启。

`CLOSED` 阶段按 `round.closesAt` 同步播放一次；等待数据时停在最后画面，收到服务结果后显示实际返回的骰子和阵营。默认静音，可通过“开启摇骰声音”开启原音；减少动态模式与加载失败时显示静态帧，自动播放受限时可手动播放。离屏与页面隐藏暂停，恢复后按当前期次时间继续。

`config.quickShakeDuration` 为 10,000ms，普通期次、体验开奖、旧演示缓存和文字提示统一为 10 秒封盘窗口。桌面使用 16:9 连续房间构图，手机聚焦荷官、双手和骰盅。标题和倒计时叠在场景两侧，画面底部柔化到同色绿绒桌面；弧形押注区叠入画面底部，筹码栏落在近处的黑色桌沿，手机控制区随内容纵向排列。

### 弧形牌桌与落筹交互

快速骰战按用户选定的第二张效果图实现。`src/pages/Quick.tsx` / `QuickTable.css` 使用独立生成的绿绒弧形牌桌、黑色皮革桌沿、黄铜四槽筹码盘和 1/5/10/50 倍透明筹码素材；照片负责材质，规则、金额、人数、选择和确认仍为真实 DOM。

默认选择豹子与 1 倍筹码。选择筹码后点击「小／豹子／大」，筹码以 520ms 落下反馈移动到当前阵营；每次替换草稿选择，不累加订单，点击「确认阵营」才进入原有报价弹窗。自定义倍数沿用整数 1–1,000,000 校验；没有对应面值图时显示 1 倍筹码与 ×倍数标记。封盘禁用阵营、筹码、倍数与确认，系统减少动态效果时取消落筹动画。

桌面牌桌素材保持 20:7 比例，按照片上的领地定位；≤600px 使用单独生成的 1170×900 手机构图，保留全部三块领地。筹码按钮的真实点击范围最小 44px，支持键盘与可见焦点；桌面装饰层不拦截声音按钮。最终对比截图与浏览器检查记录保存在 `.impeccable/review/curved-table/`，选定参考图为 `.impeccable/mocks/approved/quick-curved-table.png`。

### 3D 游戏卡片

首页两个游戏入口使用独立编写的 `src/components/TiltCard.tsx` 和同名 CSS。鼠标在卡片上移动时，整张卡片围绕 X/Y 轴轻微倾斜，暖金反光跟随指针，离开后约 480ms 复位。最大倾角为 X 轴 ±3.5°、Y 轴 ±4.5°，避免影响文字阅读和入口点击。

只在宽度超过 800px、支持精确鼠标悬停且未启用减少动态效果时启动；手机保持平整卡片，键盘焦点使用金色卡边和原有绿色轮廓。指针更新按动画帧合并，离开、滚动、窗口失焦、页面隐藏或系统偏好变化时复位，无额外依赖。

已尝试 `npx shadcn@latest add @reactbits-starter/credit-card-tw`，安装器因缺少 `REACTBITS_LICENSE_KEY` 退出；本实现没有安装、复制或冒充官方 Credit Card 组件。

### 悬停文字散开

首页 `LobbyHeadline.tsx` 与同名 CSS 独立实现 Text Scatter 风格的悬停效果。鼠标进入标题时，10 个字各自向上散开并旋转，约 1.25–1.41 秒落回原位；提前移开鼠标时约 480ms 平滑复位，再次进入可重新触发。没有点击要求、自动换句或定时循环；“幸运”沿用 `--gold`。

采用浏览器原生 Web Animations，无额外依赖。标题保持固定排版，移动的字不接收指针，避免悬停抖动。宽度 600px 及以下、触屏或减少动态模式使用静态标题；窗口失焦、页面隐藏或系统偏好变化时清理动画。读屏通过完整的标题名称读取原句。开奖阶段标签、倒计时、号码和金额直接显示数据。

已执行 `npx shadcn@latest add @reactbits-starter/text-scatter-tw`，安装器因缺少 `REACTBITS_LICENSE_KEY` 退出。当前为独立实现，没有安装或复制 React Bits Pro 官方付费组件；Starter / Pro registry 与环境变量 Authorization 配置仍保留。

### 一键同步

开发设置的“配置同步”支持编辑 / 粘贴 JSON、校验、应用与重新读取。改变配置需增加 `version`，`effectiveRound` 必须为 `NEXT`，日期、比例总和、复式注数与权重模式必须有效。

当前期次拥有独立规则快照。新经济规则只用于达到 `effectiveAt` 后开启的下一期；历史结算不重算。品牌素材路径与参考价格应用后立即更新，已有报价与订单仍保留原始金额。

### mock / real

复制 `.env.example` 为 `.env.local`。默认 `VITE_SERVICE_MODE=mock`。

`real` 模式明确显示“真实服务待接入”，所有操作接口拒绝执行，不会悄悄使用 mock。Token / 合约 / RPC 地址默认留空，不能生成真实交易。接入后应由适配器读取正确网络、服务器时间、规则与链上状态，并实现授权、参与和领奖。生产环境配置入口应保持只读。

## 计算约定与边界

- U 表示 USDT 计价单位，参与始终支付 luck。Token decimals 从环境配置读取。
- 接口金额为最小单位整数字符串；内部计算用 BigInt。U 换 luck 向上取整。
- 每日实际付款先按比例销毁，余下按五档比例进入独立金库，分档最小单位余数留在最后一档。
- 每日中奖按各档累计奖池释放 60%，按有效中奖权重分配。没有中奖的档位不释放，分配余数留在原档。
- 快速按锁定的倍数权重分配失败阵营资金，只销毁净盈利的 2%，返还实际本金。分配余数留存在该期记录。
- 模拟的其他参与者是资金 / 权重汇总，快速结算将其作为其他获奖者集合；个人页面只列当前演示钱包。
- 空胜阵营保持 `UNCONFIRMED`，结算进入 `NEEDS_REVIEW`，不实现退款或其他未确定经济规则。
- 真实钱包、Token 授权、合约、实时行情、交易税归集、链上 VRF、自动开奖、实际派奖均未接入。前端演示防重复不替代合约保护。
